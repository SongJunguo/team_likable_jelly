#### 过滤链详解（classic_dp_loop 策略）

**核心设计理念**：双层速度检测 + 多轮迭代清理，避免插值复活异常

完整过滤链（按执行顺序）：

1. **第1道防线：原始数据速度检测**（避免时间聚合误判）
   - `FilterMaxSpeed(max_speed_mps=550)`
     - 检测相邻点的 Haversine 大圆距离速度
     - 阈值：550 m/s ≈ 1980 km/h ≈ 1.62 倍音速
     - 删除策略：删除超速点对的两个点
     - 说明：商用机最大速度约 300 m/s，该阈值比正常速度宽松约1.8倍

   - `FilterAxisSpeed`（分轴独立检测，全球适用）
     - 纬度变化率：`0.0054°/s` ≈ 600 m/s
     - 经度变化率：`0.008°/s`（赤道处 ≈ 890 m/s，60°N ≈ 445 m/s）
     - 高度变化率：`164 ft/s` ≈ 50 m/s ≈ 9843 ft/min
     - 经度阈值已针对全球数据优化（避免高纬度误杀）
     - 说明：纬度阈值对应600 m/s，略宽松于FilterMaxSpeed，形成梯度防护

2. **第2-5道：清理重复与卡死数据**
   - `FilterCstLatLon`：删除经纬度重复广播
   - `FilterCstPosition`：删除三维位置卡死
   - `FilterCstSpeed`：删除速度字段卡死

3. **第6-7道：导数突刺检测**
   - `MyFilterDerivative`（默认阈值）
     - 纬度/经度：一阶 `0.004°/s`，二阶 `0.02°/s²`
     - 高度：一阶 `126 ft/s`，二阶 `50 ft/s²`

   - `FilterDerivativeLoop`（循环迭代，max_passes=10, min_passes=4）
     - 用相同阈值循环检测，直至无新增 NaN
     - 清理"3+ 连点突刺"残留

4. **第8道：边缘离群点清理**
   - `FilterEdgeOutlier`：清理段首/段尾的离群点

5. **第9道防线：间接超速检测**（捕获过滤器删除中间点后形成的超速）
   - `FilterMaxSpeedSkipNaN(max_speed_mps=550, max_iterations=5)`
     - **关键功能1**：清理部分坐标点
       - 检测"只有纬度无经度"或"只有经度无纬度"的点（约0.74%）
       - 原因：MyFilterDerivative 可能只删除单个维度，产生数据质量问题
       - 操作：将部分坐标点完全清空（避免插值时借用坐标产生异常）

     - **关键功能2**：跨越 NaN 检测速度
       - 典型场景：原始点0→点1(卡死)→点2(卡死)→点3(超速跳变)
       - 过滤后：点0 → NaN → NaN → NaN → 点7
       - 问题：点0→点7 距离大、时间长，形成间接超速（如 1428 m/s）
       - 解决：检测有效点之间的速度，删除超速点对
       - 循环策略：最多迭代5次，直至收敛
       - 阈值：550 m/s，与第1层FilterMaxSpeed保持一致

6. **第10道：孤立点兜底**
   - `FilterIsolated`：删除与其他观测相距 ≥20 秒的孤立点

#### 说明
  - 已存在的目标文件默认跳过；加 `--force` 可覆盖重跑；`--dry-run` 可仅打印命令不执行。
  - 每日日志写入输出目录下的 `.logs/YYYY-MM-DD.log`。
  - **与旧版本差异**：
    - v5 新增双层速度检测（第1层在原始数据，第9层跨NaN检测）
    - 阈值从 700-1000 m/s 收紧到 550 m/s（仍比商用机最大速度宽松约1.8倍）
    - 经度阈值优化为全球适用（0.008°/s，赤道890 m/s，高纬度不误杀）
    - 新增部分坐标点清理功能（清理约0.74%的数据质量问题点）
    - FilterMaxSpeedSkipNaN 的双重功能：部分坐标清理 + 间接超速检测
  - 整体保持"只置 NaN 不插值"的原则。
  - **重要**：双层速度检测能有效防止插值复活异常（如1550 m/s超速点）。

## 2. 重建 complete（v2：仅内部洞 + 20s 限洞）
- 脚本：`junguo_analysis_for_opensky2022/analysis_for_interpolation/regenerate_complete_all.sh`
- 默认参数已指向 v2 输出目录；直接运行：
```
bash junguo_analysis_for_opensky2022/analysis_for_interpolation/regenerate_complete_all.sh
```
- 说明：
  - 不覆盖旧目录；每日输出 `complete_YYYY-MM-DD.parquet`
  - 采用 `limit_area='inside'` 禁止头尾外推；`MAX_HOLE_SIZE=20s` 不跨大洞桥接
  - `--ids-file` 默认指向 `high_quality_flight_ids.txt`，仅对白名单（高质量航班）执行插补；若要全量处理，可替换或移除该参数

## 3. 切段（0 NaN 连续片段）
- 脚本：`junguo_analysis_for_opensky2022/analysis_for_interpolation/split_segments_all.sh`
- 默认规则：必需列 `latitude longitude altitude` 非 NaN；`Δt ≤ 20s`；`min_points=30`；`min_duration=120s`
```
bash junguo_analysis_for_opensky2022/analysis_for_interpolation/split_segments_all.sh
```
- 命名：
  - `original_flight_id`：原始 ID；`segment_index`：1..N
  - 新 `flight_id = original_flight_id * 10000 + segment_index`（int64）
  - `flight_seg_info = "{original}_s{index}_{startUTC}_{endUTC}"`

## 6. 常见问题与排错
- Parquet 读取异常（pyarrow）：
  - 临时绕过：`pd.read_parquet(path, engine="pyarrow", use_legacy_dataset=True)`
  - 低层 API：`pyarrow.parquet.read_table(path).to_pandas()`
- 斜坡/延伸：
  - v2 已禁用头尾外推、限制 20s 大洞；仍见斜坡，多半是绘图连线（中间无行），不影响底层数据。
- 并发与 I/O：
  - HDD 上建议并发 6–8；若 I/O 等待高，降低 `--procs`。
- 时间：
  - 全流程 UTC；图上的东八区仅用于展示。
