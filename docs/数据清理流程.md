# 数据清理流程（team_likable_jelly 原始实现）

> 说明：本文件仅梳理仓库根目录下的原始清洗与预处理流程，不包含 `junguo_analysis_for_opensky2022/` 目录（该目录为数据集质量检查脚本集，与原始实现无关）。

- 目标：对 OpenSky/ADS‑B 轨迹进行去噪、去异常、时序修复与平滑插值，为特征工程与建模提供一致、干净的输入。
- 产物：过滤后的轨迹与平滑/限洞插值后的轨迹（均为 Parquet），以及辅助的航班/机场时区数据。
- 入口：`Makefile` 统一编排（见下文“如何运行”）。

---

## 数据字段单位说明

本节列出轨迹数据中各字段的标准单位，与 OpenSky Network 官方文档保持一致：

### 位置与运动参数
- **经纬度**：`longitude`, `latitude` [DD, decimal degrees] [十进制]
  - 经度范围：-180° 到 +180°
  - 纬度范围：-90° 到 +90°
- **高度**：`altitude` [ft, 英尺]
  - ADS-B Reported altitude 使用 25 ft 量化步长：相邻采样只能以 25 ft 的整数倍变化（例如 …-25, 0, +25, +50 ft），任何看似“25 ft/s 台阶”的现象都源自该分辨率；调节过滤阈值时需考虑这一点。
- **垂直速度**：`vertical_rate` [ft/min, 英尺/分钟]
- **地面速度**：`groundspeed` [kt, 节]
- **航向角**：`track` [decimal degrees, 十进制度数]

### 气象参数
- **风速分量**：`u_component_of_wind`, `v_component_of_wind` [m/s, 米/秒]
- **温度**：`temperature` [K, 开尔文]

### 飞机参数
- **起飞重量**：`tow` [kg, 千克]
  - 注：TOW (TakeOff Weight) 为估算值

### 时间参数
- **时间戳**：`timestamp` [UTC, 协调世界时]
  - 格式：`datetime64[ns]` 或 ISO 8601 字符串

### 能量率参数
- **能量率**：`energyrate` [m²/s³, 平方米每立方秒]
  - 计算公式：能量率 = 功率 / 质量 = (推力 × 速度) / 质量

## 总览

清洗流程由三个核心环节串起：

1) 轨迹过滤（Filter）→ 置 NaN/删除可疑点，避免错误插值污染
2) 轨迹平滑与“限洞插值”（Interpolate）→ 使用三次平滑样条，禁止跨大缺口插值
3) 时间戳校正（可选）→ 将 ADEP/ADES 时刻与物理进出 10NM 的点对齐并微调

此外还包含基础数据准备（航班 CSV→Parquet、机场过滤与时区补充），便于时间/地理相关处理。

相关文件：
- [`Makefile`](../Makefile)
- [`CONFIG`](../CONFIG)

## 数据与目录

`CONFIG` 中的 `FOLDER_DATA` 指定数据根目录。`Makefile` 将在其下创建/使用如下目录：
- 原始轨迹：`$(FOLDER_DATA)/rawtrajectories`
- 过滤后：`$(FOLDER_DATA)/$(PREFIX_FILTER)_filtered_trajectories`
- 平滑后：`$(FOLDER_DATA)/$(PREFIX_INTERPOL)_interpolated_trajectories`
- 航班：`$(FOLDER_DATA)/flights`
- 机场+时区：`$(FOLDER_DATA)/airports_tz.parquet`

`PREFIX_*` 由 `Makefile` 中的参数决定（如平滑系数、切片参数等），可直观看到不同实验配置的产出。

### 统计方法说明
- 使用 `pyarrow.dataset`/`pyarrow.parquet` 逐批读取 Parquet 数据，批量大小 512k~1M 行，避免内存峰值。
- 对每个批次调用 `pyarrow.compute.min/max` 更新全局最小/最大值；一旦刷新极值，记录对应的 `flight_id` 与 UTC `timestamp`。
- 极端点统计通过构造布尔掩码（如 `pc.greater_equal(pc.abs(latitude), 80)`）并求和得到点数，再用 `pc.filter` 聚合满足条件的 `flight_id`。
- 原始数据目录直接使用 Dataset API 遍历 365 个日度文件；`perfect_trajectories` 子集逐文件（共 365 个）读取，同样流程得到覆盖范围。


## 跨日航班合并方案（面向序列建模的扩展）

> 需求背景：`opensky_2024_PRC_dataset/rawtrajectories` 以“自然日”切分文件，跨午夜飞行的航班会被拆成多个片段。若要训练 decoder-only Transformer 这类需要长序列上下文的模型，建议在过滤前先进行跨日合并。

### 合并目标

- 以 `flight_id` 为主键，将同一航班在不同日期文件中的记录合并成一条按时间连续的轨迹。
- 允许轨迹跨越多日，只要相邻采样之间的时间间隔小于阈值（建议 6 小时）即视为同一连续航段。
- 输出“航班级” Parquet，保留所有原字段，为后续过滤和模型切片提供输入。

### 建议的目录与文件命名

- 新建目录：`$(FOLDER_DATA)/mergedtrajectories`
- 输出文件：`<flight_id>_<startdate>_<enddate>.parquet`
  - `startdate/enddate` 取合并轨迹的首尾日期（UTC），便于溯源
  - 单航班如存在多个间隔 ≥ 阈值的段，可分别输出 `_part1/_part2` 后缀

### 实施步骤

1. **扫描阶段**
   - 使用 `pyarrow.dataset` 或 `pandas` 批量遍历 `rawtrajectories/*.parquet`。
   - 读取时保留 `flight_id` 为 `int64`，并把 `timestamp` 转换为 UTC `datetime64[ns]`。

2. **分段规则**
   - 对同一 `flight_id` 按时间排序。
   - 若相邻两个观测的时间差 `Δt` ≥ `MERGE_GAP_THRESHOLD`（建议 6h），判定为新段；否则归入当前段。
   - 允许在内存中维护一个“未完成轨迹”字典，当处理完当天数据后，对未跨阈值的段暂不写出，等待下一天追加。

3. **写出与落盘**
   - 每个段结束时写入 `mergedtrajectories`，并记录首末时间、源日文件列表。
   - 建议使用 `pyarrow.parquet.write_table` 或 `DataFrame.to_parquet`（`compression="snappy"`）以减少体积。
   - 同步生成索引表 `mergedtrajectories/_index.parquet`，包含：`flight_id`、`segment_id`、`start_ts`、`end_ts`、`source_days`，便于追踪。

4. **与过滤流程衔接**
   - 将 `filter_trajs.py` 的输入目录从 `rawtrajectories` 切换为 `mergedtrajectories`（可在 `CONFIG`/`Makefile` 中引入新的变量如 `FOLDER_MERGED`）。
   - 保持现有过滤链不变（仍只做置 NaN/不插值）。
   - 若后续步骤仍需“按日平滑/特征”，可在过滤后根据 `timestamp.date()` 重新切分成日文件；或直接在模型数据管线中按航班逐段切片成固定长度窗口。

### 运行逻辑示例

```
python3 merge_cross_day_trajs.py \
    --raw_dir   $FOLDER_DATA/rawtrajectories \
    --out_dir   $FOLDER_DATA/mergedtrajectories \
    --gap_hours 6

# 之后的清洗流程
python3 filter_trajs.py -t_in $FOLDER_DATA/mergedtrajectories/<file>.parquet \
                        -t_out $FOLDER_DATA/<prefix>_filtered/<file>.parquet \
                        -strategy classic
```

脚本 `merge_cross_day_trajs.py` 可以复用现有工具函数（如 `utils.ensure_datetime` 等），实现关键逻辑：

- 通过 `heapq` 或按日遍历的方式让数据在内存中保持近似有序；
- 一个航班同一段的数据写出后即清理缓存，控制内存占用；
- 记录日志，标明合并段的首尾时间与来源天列表，方便审核。

### Transformer 数据集构建建议

- 在过滤后，可为每段轨迹生成均匀采样的时间序列（如 1 秒或 5 秒间隔），并填补仍然存在的 NaN（未插值的部分可直接掩码）。
- 训练样本可按“固定时长窗口”（例如 10 分钟/600 点）滑动切片，附带 `attention_mask` 标记无效点；
- 若模型需要额外上下文（机场、机型、天气），可从索引表 `_index.parquet` 关联对接。

## 步骤二：轨迹过滤（Filter）

- 入口：`make cleantrajectories`
- 动作：`python3 filter_trajs.py -t_in <raw> -t_out <filtered> -strategy classic`
- 脚本：[`filter_trajs.py`](../filter_trajs.py)
- 过滤器实现：[`filterclassic.py`](../filterclassic.py)

实现要点：
- 使用 `traffic` 的 `FilterBase` 风格实现一组可组合滤波器，并显式设置 `strategy=nointerpolate`，只做“置 NaN/剔除”，不做任何插值。
- 经典策略（`classic`）滤波器链：
  - `FilterCstLatLon`：若相邻时刻经纬度均未更新，则将 `latitude/longitude` 置 NaN（判定重复广播）。
  - `FilterCstPosition`：若高度/经纬度整体未更新，则将 `latitude/longitude/altitude` 置 NaN。
  - `FilterCstSpeed`：若 `vertical_rate/track/groundspeed` 均未更新，则置 NaN。
  - `MyFilterDerivative`：基于一阶/二阶导阈值剔除“突刺点”（使用真实秒级时间差；对 `track` 先 `np.unwrap(period=360)` 再判断）。
  - `FilterIsolated`：计算每点与最近有效点的最小时间差，若与任一点相距 ≥ 20s，则将该点的观测变量置 NaN（避免孤立测量影响后续平滑/插值）。
- 变量屏蔽联动：若 `latitude` 或 `altitude` 为 NaN，则同步屏蔽天气变量（`u_component_of_wind`、`v_component_of_wind`、`temperature`）。
- 关键阈值（以源码为准）：
  - 孤立点阈值：20 秒（`FilterIsolated`）
  - 微分阈值（`MyFilterDerivative.default`）例：
    - `altitude`：一阶 200、二阶 50
    - `geoaltitude`：一阶 200、二阶 150
    - `vertical_rate`：一阶 1500、二阶 1000
    - `groundspeed`：一阶 12、二阶 10
    - `track`：一阶 12、二阶 10
    - `latitude/longitude`：一阶 0.01、二阶 0.06

### 实现细节补充（对应 `filterclassic.py`）

- `FilterCstLatLon`（重复经纬度屏蔽）
  - 判定逻辑：对 `latitude/longitude` 分别计算“是否更新”（相邻非 NaN 值不同），两者取或；若当前时刻未更新，则将 `latitude/longitude` 置 NaN。
  - 作用：剔除 ADS‑B 重复广播（同一位置重复多次），避免这些点参与后续导数与插值。

- `FilterCstPosition`（整体位置不变屏蔽）
  - 判定逻辑：`altitude/latitude/longitude` 三者只要有任意一个发生变化就视为“更新”，否则置三者为 NaN。
  - 作用：当高度与位置整体停滞时（可能是设备卡顿或重用上一帧）统一屏蔽，避免“静止位置”影响速度与导数。

- `FilterCstSpeed`（速度相关未更新屏蔽）
  - 判定逻辑：`vertical_rate/track/groundspeed` 三者均未变化时置 NaN。
  - 作用：剔除“速度未刷新”的重复广播，避免导数与突刺检测被噪音误导。

- `MyFilterDerivative`（基于一/二阶导的突刺点剔除）
  - 时间差：使用真实时间戳差 `Δt`（秒级），而非固定采样间隔。
  - 角度预处理：`track` 先 `np.unwrap(period=360)` 展平跨 0/360 的跳变。
  - 一阶导：`d1_i = |x_i - x_{i-1}| / Δt_i`
  - 二阶导：`d2_i = 2·| (x_i - x_{i-1}) - (x_{i-1} - x_{i-2}) | / (Δt_i + Δt_{i-1})`
  - 判定与屏蔽：
    - 若 `d2` 超阈值（`second`），则以三点窗口记票：`i-1,i,i+1` 分别+1；其中任一点累计票数≥2 即判为突刺，置 NaN（等价于保留“缓变”点，剔除尖锐加速度异常）。
    - 若 `d1` 超阈值（`first`），则以二点窗口记票：`i-1,i` 分别+1；累计票数≥2 置 NaN（避免单边巨大跃迁）。
  - 阈值：各变量各自配置，详见源码 `MyFilterDerivative.default`。

- `FilterIsolated`（孤立测量屏蔽）
  - 思路：对每个变量，忽略该变量为 NaN 的时刻后，计算每点与最近有效点的最小时间差 `dt_min`：
    - 先用前向/后向填充在时间轴上找到"上一/下一有效时间"，再取差值得到 `dt_min`。
  - 执行：若 `dt_min ≥ 20s`，则将该变量在该时刻置 NaN；若 `dt_min` 为 NaN 亦置 NaN。
  - **孤立点阈值**：20秒（硬编码在 `FilterIsolated` 类中）
  - 作用：避免孤立点（周围缺乏支撑点）参与平滑/插值导致"长桥接"。
- `FilterSpatialPCAOutlier`（Clean-Segment-Interpolate 策略新增）
  - 仅使用 `(latitude, longitude)` 坐标，先做零均值，再对全部点（或滑动窗口中的点）拟合第一主成分。
  - 计算每点的“重建残差”（点到主轴的垂直距离），并使用稳健阈值 `median(residual) + PCA_MAD_SCALE * 1.4826 * MAD` 判定异常；`MAD` 为残差相对中位数的绝对偏差中位数。
  - 低于 `PCA_MIN_POINTS` 时跳过检测，防止主成分被样本不足的噪声支配；`PCA_WINDOW_SIZE > 0` 时自动启用 50% 重叠滑窗复查，覆盖长航段中的局部结构。
  - 统计结果（`flagged/total/threshold` 等）写入 `PCA_STATS_CSV`（默认 `reports/quality_check_clean_v6/pca_flags.csv`），该文件通过 `fcntl` 加锁，可安全支撑多进程写入。
  - 典型用途：快速剔除像图 248867985 案例中“偏离主航迹几十度/几百公里”的孤立段，避免后续切分与插值被污染。
- `FilterMaxSpeedSkipNaN`（PCA 之后的补充检测）
  - 在 PCA 删除大部分偏航段后，再次按 `MAX_SPEED_MPS` 阈值跨越 NaN 检测端点间水平速度，直接删除超速的端点对。
  - 通过 `ENABLE_SKIPNAN_POST_PCA` 开关控制，`POST_PCA_SKIPNAN_MAX_ITER` 指定最多迭代次数（删除端点后可能出现新的间接超速，需循环直至收敛）。
  - 目标是清理那些“沿主轴方向、但时间/距离跨度过大”的跳点，为插值留下更短、更连续的段落。

- 变量屏蔽联动（天气变量）
  - 规则：若 `latitude` 或 `altitude` 为 NaN，则将 `u_component_of_wind`、`v_component_of_wind`、`temperature` 同步置 NaN。
  - 目的：确保“位置/高度不可用”时，依赖其空间位置的天气量也不被使用。

演示与教程：新增 `learn_python/trajectory_filtering_demo.ipynb` 展示如何生成一段合成轨迹、逐步应用各滤波器，并对比如下指标：异常数量、NaN 位置、关键变量曲线前后对比（含 `track` unwrap 效果）。

## 步骤三：轨迹平滑与“限洞插值”（Interpolate）

- 动作：`python3 interpolate.py -t_in <filtered> -t_out <interpolated> -smooth <平滑系数>`
- 脚本：[`interpolate.py`](../interpolate.py)
- 依赖工具：单位转换/派生变量在 [`readers.py`](../readers.py) 与 [`utils.py`](../utils.py)

实现要点：
- 单位策略：
  - 平滑前调用 `readers.convert_to_SI → add_features_trajectories → convert_from_SI`，确保后续处理在一致单位下进行，最终输出仍为“原始单位”（例如高度英尺、垂直速度 ft/min、航向角度°）。
- 轨迹预处理：
  - `track` 先前向填充/后向填充，再 `np.unwrap(period=360)` 展平角度跳变，保存在 `track_unwrapped`，原始 `track` 列被移除。
- 平滑方法：
  - 使用 `csaps` 三次平滑样条；不同变量可使用不同光滑强度（如速度、风分量等使用 `0.1 * smooth`）。
  - 对 `altitude` 额外计算一阶导并乘以 60，得到 `daltitude`（ft/min），用于后续爬升段特征。
- “限洞插值”：
  - 为每个变量计算"洞宽"（相邻有效点在时间轴上的最小距离），超过 `MAX_HOLE_SIZE = 20s` 的缺口严格不插值，保持 NaN；洞宽为 NaN 的位置同样保持 NaN。
  - **最大洞宽**：20秒（定义在 `interpolate.py` 中的 `MAX_HOLE_SIZE` 常量）
  - **参数关系说明**：孤立点阈值（20秒）和最大洞宽（20秒）是两个独立程序中的独立参数，数值相同但用途不同：
    - 孤立点阈值用于过滤阶段，剔除与其他观测相距超过20秒的孤立点
    - 最大洞宽用于插值阶段，限制插值只在20秒以内的数据缺口中进行
- 额外派生量（便于后续特征工程）：
  - `gsx/gsy`（地速向量分解）、`tasx/tasy/tas`（真空速向量及模长）、`wind`（风速模长）。
  - **能量率 (energyrate)**：单位为 m²/s³（等价于 W/kg 或 J/(kg·s)），通过总能量变化率计算得出，用于爬升段特征分析。计算公式包含重力势能、动能和风能项的时间导数。

## 时间戳校正（可选）

- 目的：将 ADEP/ADES 对齐到"进/出机场 10 nmi"处的物理时刻，并用合理的爬升/下降率微调。
- 脚本：[`correct_date.py`](../correct_date.py)
- 方法：
  1. 将轨迹与机场表 join，并用大圆距离计算与 ADEP/ADES 的距离（海里）。
  2. 在 10 nmi 内，ADEP 选"最晚点"、ADES 选"最早点"。
  3. 用高度和阈值率（默认 ADEP：+1000 ft/min，ADES：-1000 ft/min）进行回推/前推，得到 `t_adep/t_ades`。
  4. 若无法校正（如缺少点），回退到原始 `actual_offblock_time + taxiout_time` / `arrival_time`。

## 注意事项

- 本流程严格避免“跨大洞插值”，优先将“重复/未更新/突刺/孤立”等异常置 NaN，再在有效段内进行平滑。
- `traffic` 滤波仅用于筛除/置 NaN，不进行轨迹插值；插值仅在 `interpolate.py` 中、且受 20s 限制。
- 过滤与平滑过程中，会统一 `flight_id/icao24` 的类型为 `int64`，避免后续 join/groupby 出错。
- 若需调整灵敏度，可从 `Makefile`（平滑系数）、`filterclassic.py`（微分/孤立阈值）、`interpolate.py`（最大洞宽）三处入手。
