# 高性能数据质量检测工具使用指南

## 📊 核心发现

基于新的高性能数据质量检测工具 `check_data_quality_polars.py` 的**大规模分析结果**（30天样本）：

### 🔍 原始数据质量（30天实测数据）
- **总数据规模**: 351,717,077 轨迹点，55,235 唯一航班
- **日均数据量**: 11.7M 轨迹点，1,841 航班
- **缺失值情况**:
  - `groundspeed`: 1,040,402 (0.296%) 
  - `track`: 1,040,402 (0.296%)
  - `vertical_rate`: 1,554,092 (0.442%)
- **数据范围异常**:
  - `altitude`: 125,284 超出范围 (0.036%)
  - `groundspeed`: 44,343 超出范围 (0.013%)
  - `vertical_rate`: 32,206 超出范围 (0.009%)
- **轨迹完整性**:
  - 平均每航班: 6,368 轨迹点
  - 中位数: 4,735 轨迹点
  - 范围: 18 - 36,871 轨迹点

### ⚠️ 插值数据质量问题（严重）
- **大规模数据缺失**:
  - `latitude/longitude`: ~13.8% 缺失
  - `groundspeed`: 21.985% 缺失  
  - `TAS相关字段`: 28.199% 缺失
  - 相比原始数据，缺失率增加40-100倍

### 💡 关键结论
1. **原始数据质量优秀**: 缺失值<0.5%，异常值<0.1%，非常适合机器学习
2. **插值处理严重降质**: 引入13-28%缺失值，系统性破坏数据完整性
3. **推荐使用原始数据**: 用于轨迹预测和TOW预测任务
4. **大规模可行性**: 全年预计4.2亿轨迹点，670万航班，充足训练数据

### 🎯 性能预估（基于30天实测）
- **全年数据规模**: ~4.27亿轨迹点，~67万航班
- **存储需求**: ~280GB parquet文件
- **处理性能**: 80核CPU + 512GB内存可在15分钟内完成全量分析

## 🚀 工具使用说明

### 基本用法

```bash
# 快速测试 - 只处理前5天
python check_data_quality_polars.py --limit 5

# 处理特定日期范围
python check_data_quality_polars.py --start-date 2022-01-01 --end-date 2022-01-31

# 只分析原始数据，跳过插值数据
python check_data_quality_polars.py --skip-interp --skip-comparison

# 全量分析（365天，需要较长时间）
python check_data_quality_polars.py
```

### 使用便捷脚本

```bash
# 给脚本添加执行权限
chmod +x run_quality_check.sh

# 快速测试
./run_quality_check.sh -l 5

# 处理1月数据
./run_quality_check.sh -s 2022-01-01 -e 2022-01-31

# 全量分析，优化线程配置
./run_quality_check.sh -j 80
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--limit N` | 限制处理文件数量 | `--limit 10` |
| `--start-date` | 开始日期 | `--start-date 2022-01-01` |
| `--end-date` | 结束日期 | `--end-date 2022-01-31` |
| `--skip-interp` | 跳过插值数据分析 | |
| `--skip-comparison` | 跳过数据对比 | |

## ⚡ 性能优化

### 系统配置
- **CPU**: 80核心，充分利用并行处理
- **内存**: 512GB，支持大规模数据加载
- **存储**: ~280GB数据，365个parquet文件

### Polars优化特性
- **Lazy evaluation**: 延迟计算，减少内存占用
- **列式存储**: 高效的parquet文件处理
- **多线程并行**: 自动利用所有CPU核心
- **内存映射**: 大文件流式处理

### 预期性能
- **小规模测试** (2天): ~2-5秒
- **中等规模** (30天): ~23秒（实测）
- **月度分析** (31天): ~30-60秒
- **季度分析** (90天): ~2-3分钟
- **全量分析** (365天): ~10-15分钟

## 🎯 使用建议

### 对于轨迹预测任务
1. **使用原始轨迹数据** (`rawtrajectories/`)
2. **预处理策略**: 处理0.326%的缺失值
3. **异常值处理**: 过滤超出合理范围的数据点

### 对于大规模分析
1. **分批处理**: 使用`--limit`参数先测试
2. **日期范围**: 使用`--start-date`和`--end-date`
3. **内存监控**: 使用`htop`监控系统资源

### 对于生产环境
1. **使用tmux/screen**: 长时间运行任务
2. **日志记录**: 重定向输出到文件
3. **错误处理**: 脚本包含详细的错误处理机制

## 🔧 故障排除

### 常见问题
1. **内存不足**: 减少`--limit`参数
2. **文件路径错误**: 检查`--raw-dir`和`--interp-dir`参数
3. **Polars未安装**: `conda install -c conda-forge polars`

### 性能调优
1. **增加线程数**: 设置环境变量`POLARS_MAX_THREADS=80`
2. **SSD存储**: 确保数据存储在高速SSD上
3. **减少I/O**: 使用本地存储避免网络文件系统
