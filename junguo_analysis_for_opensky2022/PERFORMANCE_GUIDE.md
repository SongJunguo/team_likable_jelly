# 高性能数据质量检测工具使用指南

## 📊 核心发现

基于新的高性能数据质量检测工具 `check_data_quality_polars.py` 的分析结果：

### 🔍 原始数据质量（前2天样本）
- **总轨迹点数**: 27,868,671
- **唯一航班数**: 4,190  
- **缺失值情况**:
  - `groundspeed`: 90,738 (0.326%)
  - `track`: 90,738 (0.326%)
  - `vertical_rate`: 90,737 (0.326%)
- **数据范围异常**:
  - `altitude`: 7,740 超出范围 (0.028%)
  - `groundspeed`: 5,107 超出范围 (0.018%)
  - `vertical_rate`: 1,070 超出范围 (0.004%)

### ⚠️ 插值数据质量问题
- **严重的数据缺失**:
  - `latitude/longitude`: ~14.3% 缺失
  - `groundspeed`: 24.855% 缺失
  - `tasx/tasy/tas`: 31.468% 缺失
  - 新增字段大量缺失

### 💡 关键结论
1. **原始数据质量优秀**: 缺失值仅0.326%，非常适合机器学习
2. **插值处理降低质量**: 引入大量缺失值（14-31%），不推荐使用
3. **推荐使用原始数据**: 用于轨迹预测和TOW预测任务

## 🚀 工具使用说明

### 基本用法

```bash
# 快速测试 - 只处理前5天
python check_data_quality_polars.py --limit 5

# 处理特定日期范围
python check_data_quality_polars.py --start-date 2022-01-01 --end-date 2022-01-31

# 只分析原始数据，跳过插值数据
python check_data_quality_polars.py --skip-interp --skip-comparison

# 全量分析（365天，需要较长时间）
python check_data_quality_polars.py
```

### 使用便捷脚本

```bash
# 给脚本添加执行权限
chmod +x run_quality_check.sh

# 快速测试
./run_quality_check.sh -l 5

# 处理1月数据
./run_quality_check.sh -s 2022-01-01 -e 2022-01-31

# 全量分析，优化线程配置
./run_quality_check.sh -j 80
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--limit N` | 限制处理文件数量 | `--limit 10` |
| `--start-date` | 开始日期 | `--start-date 2022-01-01` |
| `--end-date` | 结束日期 | `--end-date 2022-01-31` |
| `--skip-interp` | 跳过插值数据分析 | |
| `--skip-comparison` | 跳过数据对比 | |

## ⚡ 性能优化

### 系统配置
- **CPU**: 80核心，充分利用并行处理
- **内存**: 512GB，支持大规模数据加载
- **存储**: ~280GB数据，365个parquet文件

### Polars优化特性
- **Lazy evaluation**: 延迟计算，减少内存占用
- **列式存储**: 高效的parquet文件处理
- **多线程并行**: 自动利用所有CPU核心
- **内存映射**: 大文件流式处理

### 预期性能
- **小规模测试** (2天): ~2-5秒
- **月度分析** (31天): ~1-2分钟
- **全量分析** (365天): ~10-20分钟

## 🎯 使用建议

### 对于轨迹预测任务
1. **使用原始轨迹数据** (`rawtrajectories/`)
2. **预处理策略**: 处理0.326%的缺失值
3. **异常值处理**: 过滤超出合理范围的数据点

### 对于大规模分析
1. **分批处理**: 使用`--limit`参数先测试
2. **日期范围**: 使用`--start-date`和`--end-date`
3. **内存监控**: 使用`htop`监控系统资源

### 对于生产环境
1. **使用tmux/screen**: 长时间运行任务
2. **日志记录**: 重定向输出到文件
3. **错误处理**: 脚本包含详细的错误处理机制

## 🔧 故障排除

### 常见问题
1. **内存不足**: 减少`--limit`参数
2. **文件路径错误**: 检查`--raw-dir`和`--interp-dir`参数
3. **Polars未安装**: `conda install -c conda-forge polars`

### 性能调优
1. **增加线程数**: 设置环境变量`POLARS_MAX_THREADS=80`
2. **SSD存储**: 确保数据存储在高速SSD上
3. **减少I/O**: 使用本地存储避免网络文件系统
